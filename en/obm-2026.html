Broadcast, Don't Replicate: Eliminating Weight HBM in Datacenter LLM Serving

Problem: datacenter LLM inference is bottlenecked by memory capacity and bandwidth; weights are read-only and identical across instances yet replicated in local DRAM on tens of thousands of accelerators, incurring capex, static power and redundant fetch energy.
Where the evidence sits: Optical Broadcast Memory (OBM) has a central memory server continuously broadcast weights that inference nodes passively tap with receive-only co-packaged optics, delivering parameters directly to compute units without intermediate buffering; dynamically sized slack accommodates long and variable contexts, and the layout is shown to serve MoE models; at 80,000 accelerators it eliminates petabytes of HBM while matching or beating HBM throughput and energy per token.
What the authors say about limits: an architecture and scale simulation, not a built datacenter; depends on co-packaged optics and fibre-broadcast engineering maturity; the failure domain moves from a single node to the central memory server, with reliability and maintenance not detailed; the 80k-accelerator assumption is still far from real workloads and topologies; no itemised cost model.
What it does not claim: a retrofit for existing clusters; that HBM is useless; that it is commercially available.
